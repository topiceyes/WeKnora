# 跨工作空间转让的写入协调

跨空间转让会复制文件、提交数据库事务并清理源文件。整个过程持有独占文件锁，普通知识库操作持有共享锁。锁存放在 `LOCAL_STORAGE_BASE_DIR/.kb-transfer-locks`，没有设置该变量时使用 `/data/files`。

所有服务实例和任务进程必须运行同一版本，并挂载同一支持跨进程文件锁的可写存储卷。升级时应先停止旧实例和旧任务消费者，再启动新版本；旧版本不参与这个协议。部署前需要在实际存储类型上验证锁能跨实例生效。锁由操作系统在进程退出时释放，不依赖超时租约；锁文件不能手动删除，否则旧文件和新文件可能形成两套互不排斥的锁。

当前屏障覆盖全部知识库写入，普通操作仍可并行。迁移前若有任何知识库写入或后台任务正在运行，转让返回冲突，稍后可重试；迁移期间所有知识库的新写入返回 409，后台任务等待屏障释放或自身取消。这个范围有意包含跨库批量操作、尚未解析出知识库 ID 的操作，以及资源绑定。大库转让会短暂影响其他知识库的写入。

保护接在服务入口，覆盖上传、内容编辑与版本恢复、FAQ、文档和分块操作、知识库配置及删除、Wiki 页面与目录、数据源同步、资源绑定、共享关系与组织成员变更，以及 Redis/Lite 后台任务。HTTP 写请求在权限检查加载资源快照前也取得共享锁。定时同步、清理与任务最终失败回调同样参与。脱离请求执行的手动解析在启动 goroutine 前单独保留共享锁。

Redis 队列预检会阻止仍有待执行、延时、重试或活跃任务的知识库转让，检查失败也会中止。任务执行前在共享锁内核对数据库中的当前空间，忽略已完成迁移前排入的旧任务，避免按旧路径或模型配置写入。旧数据源同步会关闭其运行记录；其他实例残留的定时同步闭包使用重新加载的数据源空间，而不是注册时的空间。

未安装协调器的服务拒绝跨空间转让。锁获取失败时，生产写入不会绕过保护继续执行。读取通常不占用写屏障；会创建默认索引页或访问授权记录的读取仍需取得共享锁。

验证覆盖共享写入与独占迁移互斥、嵌套和异步引用保留、过期上下文不能绕过迁移、进程退出释放锁、HTTP 与批量入口、整库迁移成功、旧任务退出、定时同步空间刷新，以及排队任务阻断。

配额预检仅用于提前反馈。迁移提交事务还会按租户 ID 升序锁定源、目标租户行，重新读取目标配额与已用空间，并通过带配额和整数溢出条件的原子增量更新扣减余额。普通配额写入使用同一租户行锁，因此提交前发生的配额调整或空间占用不会被迁移覆盖。额度不足时回滚数据库并清理本次复制的目标文件，保留源文件。
