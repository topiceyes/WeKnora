# 独立文档工作台

## 目标与入口

为日常阅读和写作提供独立界面，直接通过“知识库 → 文档”访问内容。

- `/platform/documents`：知识库首页，显示当前空间及共享给用户的文档知识库。
- `/platform/documents/:kbId?doc=:documentId`：目录、正文、正文大纲；链接支持刷新和浏览器前进、后退。
- `/platform/documents/:kbId?new=1`：在同一工作区新建文档。
- 平台侧栏和知识库管理页均有“文档工作台”入口。

工作台路由与平台路由并列，不继承平台的全局侧栏、聊天记录、助手面板和资料管理页头。专注模式进一步收起知识库目录与正文大纲。

## 数据与编辑

复用现有知识库、目录、正文、编辑器、版本历史和权限接口。同一篇文档在两个入口下有相同的 ID 和正文，不迁移或复制数据。FAQ 保持使用专用管理界面。

新建文档调用手工文档接口，保存为 `draft`，团队可在目录中阅读；保存不触发 AI 索引。已有文档通过正文编辑接口保存，沿用版本检查与冲突处理。AI 检索与索引设置继续在资料管理入口维护。

切换文档、切换知识库、返回首页或离开工作台时检查未保存内容，用户可继续编辑或明确放弃。刷新、关闭页面使用浏览器的离开提示。手动保存期间暂时禁止离开及继续输入，自动保存期间可继续输入；失败时保留编辑内容。支持 Ctrl/Cmd+S。

权限优先采用服务端返回的有效权限。跨空间只读授权不能被本地空间管理员身份提升；归宿人仍遵守已有 Contributor 角色下限。

## 本轮范围与后续

本轮完成独立入口、布局，以及阅读、新建、编辑、保存的基本闭环。知识库创建、成员和权限、目录整理、导入和 AI 设置仍在原管理界面。

目录内新建和移动、协同编辑、评论和语雀迁移需要继续设计。平台默认首页未改变。

## 验证

权限和页面状态测试覆盖只读共享、归宿人角色下限、文档链接、切库请求竞态、未保存提示、创建失败保留草稿，以及新建文档不触发索引。复用编辑器的 Markdown 往返测试和现有知识库回归测试。

## 编辑器增强

已补充：

- 段落样式及 H1–H4、行内代码、清除格式；选中文字显示格式工具条。
- 在段落开头输入 `/`，筛选并插入标题、列表、待办、表格、图片、公式、代码和 Mermaid；支持方向键、Enter、Escape，输入法组合输入期间不接管按键。
- 表格上方/下方加行、左侧/右侧加列、删行/列/表格，合并及拆分单元格、切换表头、拖动列宽。Markdown 投影展开合并单元格位置，保留所有单元格的文字。
- 代码块语言选择。
- 编辑区内 Ctrl/Cmd+F 查找，逐个定位、单次或全部替换；按字面内容匹配，大小写敏感，可跨加粗等格式边界，不跨段落。全部替换可一次撤销。
- 图片多选上传、粘贴和拖入；上传锚点随正文编辑映射，避免上传完成后插错位置。单张上限与服务端一致为 10 MiB。上传中阻止保存及工作区内离开。
- 图片说明编辑；受保护资源使用鉴权预览，Markdown 保留稳定资源引用，不写入临时 blob URL。
- 空白编辑提示及非空白字符统计。

实现继续基于现有 Tiptap 与 ProseMirror；交互层参考其[自定义菜单](https://tiptap.dev/docs/editor/getting-started/style-editor/custom-menus)、[表格](https://tiptap.dev/docs/editor/extensions/nodes/table)和[文件处理](https://tiptap.dev/docs/editor/extensions/functionality/filehandler)接口思路，未新增依赖。

### 结构化正文与格式保真

正文以版本化 Tiptap JSON 保存到 `metadata.document`：

```json
{"schema_version":1,"content":{"type":"doc","content":[]}}
```

该示例展示信封结构，实际正文至少包含一个有效块。前端与后端使用固定节点及属性白名单；未知版本、未知节点、无效表格或不安全的 URL 均不能作为正文保存。限制为 2 MiB、64 层及 20,000 个节点，表格最多 500 行、100 列。

- 新增文字高亮、文字颜色及信息、提示、警告、危险四类提示块，编辑、阅读及历史预览共用格式定义。
- 合并位置、跨行、列宽和单元格多段落保存在结构中，打开编辑器时优先加载 JSON。
- `metadata.content` 继续存放 Markdown。结构存在时由后端生成投影，不信任客户端同时提交的 Markdown；索引、资源绑定及旧导出接口沿用该投影。
- 旧 Markdown 文档无需批量迁移。阅读保持原样，编辑并提交时才生成结构化正文。
- 旧手工编辑弹窗遇到结构化文档会转到文档工作台。服务端拒绝缺少结构的改文请求，防止旧客户端将丰富格式压平；仅改标题或状态且 Markdown 未变时保留原结构。
- 详情和目录响应携带 `document_schema_version: 1`。前端写入结构前检查能力，并校验保存回执，旧后端不能静默丢弃 JSON 后让前端清掉恢复副本。
- 修改检测、自动保存和本机副本均包含 JSON 指纹，因此仅改颜色、提示类型或列宽也会保存。自动保存期间继续输入的格式不被旧响应替换。
- 版本快照增加独立 `document` 列（PostgreSQL JSONB / SQLite TEXT）。历史预览保留丰富格式；文本一致但结构不同的版本比较会提示有格式差异。历史恢复支持在旧 Markdown 与结构化版本之间往返。

数据库升级使用 `000904_structured_document`，正常后端启动自动执行。部署须同步更新前后端，确认迁移完成。回滚该迁移会删除版本快照的结构列；需先备份，该 down 迁移不应作为常规回退动作。当前正文结构仍保留在知识元数据中。

### 后续边界

继续基于现有 Tiptap 与 ProseMirror，未新增依赖。Word、网页等外部富文本粘贴只保留当前支持的节点和格式，不保证像素级还原。Markdown 导出保留文本与基本结构，颜色、列宽、合并布局等仍需以 JSON 为准，尚未提供独立的富格式导出包。

多人实时协同、行内评论、附件卡片、完整 Office 表格粘贴及语雀批量迁移仍需要后续实现；本轮不声称与语雀功能完全对齐。

## 自动保存与本机恢复

独立文档工作台现已提供以下行为：

- 已有文档停止输入 1.8 秒后尝试自动保存，连续保存的最小间隔为 10 秒，避免每个输入事件都新增历史版本。复用现有正文保存接口，携带 `base_version`，不触发 AI 索引。
- 自动保存保持编辑状态。请求期间允许继续输入；响应仅推进已提交快照的版本和基线，后续输入保留在编辑器及恢复副本中，不被旧响应替换。
- 保存失败保留内容，暂停自动重试；手动重试或浏览器恢复联网时可再次尝试。版本冲突不会因恢复联网自动重试，必须显式处理。
- 冲突操作为继续编辑、加载最新或强制覆盖。关闭弹窗等同于继续编辑；加载最新须明确确认放弃当前修改，加载失败仍保留编辑内容。强制覆盖是独立的明确按钮。
- 新建文档首次提交前只自动保存本机草稿，不自动发送创建请求。手动保存成功后进入正文页；避免自动重试创建导致重复文档。
- 本机副本在修改后 250 毫秒保存，并在页面隐藏、离开页面或组件卸载时尝试立即落盘。命名空间包含用户、当前空间、知识库、文档与编辑会话 ID，多个标签页各存自己的副本。
- 刷新后展示可预览的恢复副本，用户明确选择恢复或丢弃。恢复旧版本草稿时保留原始基线并暂停自动保存，不能自动覆盖较新的服务器正文。
- 保存成功或用户明确放弃当前修改后，仅移除本次编辑及已恢复的原副本。移除前比较内容、版本和时间，避免删除另一标签页刚更新的副本。
- 本机存储不可用或容量不足时显示保存失败提示，不声称本机已保存。图片上传期间继续阻止提交和离开。

这些本机副本仅在当前浏览器和站点内有效，不是服务端草稿或跨设备同步。250 毫秒防抖与页面生命周期落盘不能保证浏览器/系统突然崩溃前最后几个输入必定写入。服务端自动保存沿用已有版本检查，不提供多人实时合并。

验证覆盖恢复副本隔离、同一标签页重开恢复、存储配额失败、旧副本比较删除、自动保存防抖、上传等待、断网暂停、并发输入保留，以及恢复旧版本后的冲突阻断。

## 外部内容粘贴

文档工作台通过编辑器剪贴板管线处理外部内容，无新增依赖：

- 支持外部 HTML 中的文字颜色、高亮、加粗、标题和标准列表。颜色规范化为不透明的十六进制值；不保留任意 CSS 表达式或网页整体样式。
- HTML 表格保留跨列、跨行、单元格多段落及对齐。读取 `colgroup`、单元格的像素/磅宽度；磅按 96 dpi 换算。百分比宽度不会猜成固定像素。
- 多行多列 TSV 文本可直接粘贴为可编辑表格，支持引号中的制表符、换行、双引号及空单元格；最多 500 行、100 列及 500,000 字符。非矩形或不完整 TSV 回退普通文本，不截断内容。
- Ctrl/Cmd+Shift+V 保持纯文本粘贴；代码块保留代码。在已有表格内粘贴 TSV 不额外创建嵌套表格；尚未实现按所选矩形批量填充单元格。
- 剪贴板同时携带 HTML 正文和预览图片时优先保留正文，避免仅上传预览而丢失文字。单独截图仍沿用图片上传。
- 从本系统阅读器复制受保护图片时使用稳定资源引用。无法直接保存的本机、临时或内嵌图片保留说明占位并提示上传，不写入无法跨页面使用的地址。
- 列表的 `tight` 属性纳入服务端结构校验，并校验为布尔值，修复粘贴标准列表后被后端拒绝的问题。菜单监听器在编辑器引用初始化后注册，防止首次进入编辑时抛出初始化错误。

这并非完整 Word 导入：基于 Word 私有样式而非标准列表标签的编号、浮动布局、字体大小、分页以及复杂图形不保证还原。验证使用真实粘贴事件、保存/刷新流程和 PostgreSQL 临时知识库；另覆盖单次撤销及纯文本粘贴回退。

## 目录管理与导航（2026-11-09）

工作台已支持文件夹新建、重命名、移动及删除空文件夹，文档多选批量移动（每批最多 200 篇）、同级混合排序和拖入文件夹/根目录。拖拽目录行的中部用于移入，顶部/底部用于同级排序；上移/下移菜单提供无需拖拽的替代操作。名称、最近编辑排序只改变展示，切回手动排序仍使用服务端顺序。目录筛选/搜索期间不启用改变隐藏节点顺序的拖拽。

新表 `knowledge_navigation`（000905，PG/SQLite）保存显式空目录、直接子项顺序和共享修订号。原有路径自动参与目录树，无须一次性迁移。`PUT /knowledge-bases/:id/knowledge/navigation` 接收 `create_folder` / `delete_folder` / `move_folder` / `move_documents` / `reorder`，要求 `base_revision`。使用导航行锁和事务；过期版本返回 409，不静默覆盖。新界面遇到同名目标拒绝合并，原重命名 API 继续保留已有合并契约。

删除文件夹仅删除空目录及空子目录，服务端拒绝删除含文档的子树。移动不更改正文、历史版本或索引，不推进正文更新时间。通用整行正文/处理更新排除 `FolderPath`，避免慢任务写回旧路径；路径仅由专门的目录操作更新。知识库空间转移同步迁移导航表，知识库删除同步清理导航记录。

面包屑可进入文件夹，文件夹视图列出直接子项；当前目录内新建文档通过创建请求的 `folder_path` 原子保存目的位置，本机恢复副本同时保存该位置。目录操作调用现有未保存确认，用户选择继续编辑时不发出目录写请求。

收藏和最近访问使用独立的用户/空间/知识库浏览器存储，仅缓存 ID，不授予权限；切换身份不共享记录。支持展开全部、折叠全部、定位当前文档，Ctrl/Cmd+K 聚焦树搜索，Ctrl/Cmd+Alt+N 在当前目录新建。最近编辑用排序选项访问。

验收覆盖事务回滚、跨库批量移动拒绝、空目录持久化、路径溢出/自循环防护、重复排序项、有效共享权限、旧客户端操作与慢正文更新、空间迁移和删除清理。真实 Chrome + PostgreSQL 验证工作台操作与刷新持久化；测试使用临时知识库并清理。

开发记录每期归档到 `docs/knowledge-base/`，并同步用户原本地 Obsidian 知识库，详见仓库 `AGENTS.md`。


## 文档评论与讨论（2026-11-10）

需求：在独立阅读页围绕正文讨论，支持回复、解决/重开、本人删除及引用选区。评论独立于正文和历史版本，沿用现有文档权限，不改变索引状态。

- 存储：`knowledge_comments`，迁移 `000906` 同时覆盖 PostgreSQL/SQLite。以稳定文档 ID 关联，读取前由实际文档解析租户与知识库授权，避免维护会因移动而失效的冗余权限绑定。移动/空间迁移保留评论，复制产生的新文档不继承评论。
- API：`GET /knowledge/:id/comments?offset=0&status=all|open|resolved`，每页 20 个根讨论，回复按时间升序；`POST /knowledge/:id/comments` 接收正文、父根评论、可选选区和 `client_id`；`PUT /knowledge/:id/comments/:comment_id` 接收 `action=resolve|delete`、`base_revision` 和解决状态。
- 写入：内容最多 5000 字、引用最多 1000 字、上下文各 64 字、每根最多 100 回复。相同 UUID 和载荷支持去重重试。锁定并复核文档绑定，拒绝未完成移动/删除状态。解决或删除的根讨论不接受回复。删除清除文本/引用但保留回复。删除事务先锁文档再清理评论，避免与评论创建交错留下孤立记录。
- 权限：读沿用 Viewer；写沿用创建者或 Admin 且实际 Editor 授权。本人才能删除自身评论；根讨论的解决/重开由现有可编辑者操作。只有读授权的跨空间 Admin 不能写。API Key 合成用户禁止评论写入，作者名称由服务端读取，不能由请求指定。
- 选区：从阅读 DOM 提取引文、上下文、版本；创建时服务器检查正文版本，定位时同版本且唯一匹配才选中原文。变化/歧义提示引用不可定位，不修改结构化正文，也不猜测跨版本位置。
- 界面：按需加载的讨论抽屉；全部/未解决/已解决、刷新、更多讨论、评论/回复、解决/重开、本人删除。关闭抽屉保留本页输入，导航前提醒，发送期间阻止离开。无成员通知、实时协作、评论编辑和持久化评论草稿。
- 验证：160 项针对性前端测试、类型检查、生产构建、10 项样式守卫；Go types/repository/database 完整测试与评论/权限/迁移针对性测试通过。真实 handler/service/SQLite 的 HTTP 测试通过；Chrome 完全隔离 API 数据的 UI 验收通过。不能将隔离 UI 测试称为真实登录端到端联调；原脚本读取数据库会话令牌被自动审批拒绝，未执行。
- 本地运行：后端健康，PostgreSQL 906 clean 且评论表存在，前端入口 8081。真实用户登录后的端到端验收仍待验证。

## 全文搜索、文档链接与反向链接（2026-11-10）

目标：当前知识库内按最新正文查找知识，编辑时选择目标文档，阅读时返回引用来源。

- `GET /knowledge-bases/:id/knowledge/document-search` 复用该库 Viewer 读授权，`query` 最多 100 字，`offset` 为 0–10000，每页 20 篇。逐行读取范围内文档及必要分块，搜索至本页加一条即结束，10 秒超时；无新索引或数据库迁移。
- 结构化正文按文本节点与块边界投影，跨行内格式连续匹配，链接 URL 不作为可见正文。已有保存正文抑制旧 AI 分块；未在线编辑的已解析文件回退 `text/parent_text`。摘要、FAQ、正在删除和已软删文档排除。没有正文的处理中/失败文件不使用旧分块冒充可读内容。
- 返回命中字段、当前标题/目录及最多约 180 字的片段。Vue 文本渲染和字面高亮，特殊字符不进入 SQL LIKE 或不受控正则。
- 编辑器工具栏及 `/` 菜单使用同一搜索弹窗插入标准链接 mark。无选区插入标题，有选区保留原文字并加链接；bookmark 随事务映射。链接只存 `/platform/documents/open/<UUID>`。解析页通过正常文档详情权限检查后定位当前知识库，不依赖旧目录或标题。
- `GET /knowledge/:id/backlinks` 首先验证目标的读权限和实际持久化归属，再扫描当前库保存结构中的链接 mark。仅接纳标准、无主机/查询/hash 的内部路径；代码块、外部网站同路径、自引用及其他知识库来源不计入。纯 Markdown/原始导入链接暂不建立反向引用。
- 工作台的正常内部链接点击走路由守卫，继承未保存正文/评论提示；修饰键点击保留浏览器行为。底部反向链接可刷新和分页。
- UI 使用 250 毫秒防抖、请求代次隔离、关闭时卸载弹窗 DOM、失败重试及结果去重。Ctrl/Cmd+K 进入全文搜索，标题树筛选继续保留。
- 验证：169 项前端测试、类型检查、生产构建、10 项样式守卫；Go types/repository/database 完整测试与检索/评论/权限/迁移针对性测试；真实 HTTP/SQLite 测试及 PostgreSQL 临时表查询兼容性验证。隔离 Chrome 验证实际插入、刷新、跳转、反向链接、重命名/目录移动和删除目标错误页；真实用户登录端到端联调仍待完成。
- 边界：当前库字面扫描，无大规模性能验证、语义检索、跨块短语合并或自动改写引用显示标题。详情见 [[WeKnora文档工作台-全文搜索与文档链接]]。
