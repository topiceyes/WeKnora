# WeKnora 文档工作台浏览正文排版

- 日期：2026-11-12。
- 关联：[[文档工作台-归档索引]]、[[WeKnora文档工作台-阅读布局与导航优化]]、[[WeKnora文档工作台-自动保存与结构化正文]]。

## 需求背景与原因

用户反馈编辑知识文档时排版正常，保存后浏览显得拥挤，尤其是行距，希望获得接近语雀的阅读体验。代码检查确认：富文本编辑器显式设置 1.75 倍行高和段落外边距；阅读器使用旧公共 Markdown 样式，未指定正文行高，并通过后置 `p { margin: 0; }` 清除了段距。两者的字号、标题和引用样式也不同。这是展示样式问题，本期未更改保存内容或数据库。

## 设计决策与实现范围

- 新增文档阅读专用 `documentReading.less`，替换 DocReader 的旧 Markdown 样式引用，并由历史版本预览独立引用，兼容抽屉传送到页面外层的情况。
- 正文 16px、1.75 倍行高（28px）、普通段落下间距 12px；标题按 28/24/20/18px 区分层级，保持现有居中阅读宽度与响应式布局。
- 统一列表、引用、提示块、表格、图片及代码块间距。保留结构化正文中的空段落、图片尺寸与对齐；长代码在代码块内部滚动。
- 使用现有主题颜色变量适配深色主题。样式限定于文档阅读及历史预览，不调整编辑器和聊天排版。

## 验证结果

- 前端类型检查通过；生产构建通过，仍有既有大包提示。
- 相关结构化正文、编辑器、保存和历史模型测试 59 项通过。
- 隔离 Chrome 使用合成 API 文档验证 Markdown 浏览、结构化编辑与自动保存、返回阅读、刷新后重读，正文实际为 16px/28px，普通段距 12px。
- 浏览器验证标题层级、空段落、列表、表格、提示块、长代码内部滚动及无运行时错误；1440px 桌面、760px 窄屏无页面横向溢出，已查看桌面与深色截图。
- 打开历史版本抽屉验证预览实际为 16px 字号、28px 行高，确认独立引用样式生效。
