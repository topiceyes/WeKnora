## 发现及修复

### 普通 HTTP 环境下拖拽和评论可能报错

块拖拽及评论请求 ID 直接依赖 `crypto.randomUUID()`。localhost 属于浏览器认可的安全上下文，已有验收可通过，但普通非本机 HTTP 域名没有这个方法，会在开始拖拽或发送前抛错。

新增共用 UUID v4 工具，使用普通 HTTP 下仍可用的 `crypto.getRandomValues()`，设置正确版本及 variant 位。仅替换块拖拽令牌和评论客户端请求 ID；不使用弱随机数，也不修改登录或权限机制。评论在失败重试时继续复用相同 ID。

新增测试明确移除 `crypto.randomUUID`，验证拖拽完成、UUID 格式及评论重试 ID 稳定。浏览器使用仅映射到本机的普通 HTTP 测试域名，实际断言 `isSecureContext === false`、原生 UUID 方法缺失和随机字节接口可用，再验证拖拽与评论发送。开发服务和生产构建预览两条路径均通过，接口全部为合成响应。

### 容量检查漏计编辑器自动追加的段落

StarterKit 在正文末节点不是段落时自动追加一个可写空段落。原先块操作只检查主事务的文档，恰好 20,000 节点的文档把末尾段落移到前面后，会在检查之后再补出第 20,001 个节点，导致结果超出保存上限。

新增失败用例先复现，再将可预测的末尾段落纳入容量预检。块操作与表格粘贴共同使用这一检查，原始编辑事务及撤销逻辑保持不变；超限整次拒绝，正文及撤销栈保持原样。检查继续包含节点数、深度、表格尺寸/跨度、UTF-8 JSON 大小及服务端 HTML 字符转义。
