# WeKnora 文档工作台 v1.8.7 部署验收

- 日期：2026-11-10。
- 关联：[[文档工作台-归档索引]]、[[WeKnora文档工作台-v1.8.7发布回归]]。
- 需求：完成版本部署，保留既有扩展功能；公开记录仅保留通用设计、验证和回滚边界。

## 设计决策与实现范围

以已发布的 v1.8.7 为基线升级应用与前端，保留既有摘要相关扩展、原生解析能力和检索兼容配置。没有代码或依赖变化的辅助服务继续使用已验证版本。所有应用进程统一切换，避免新旧消费者混跑。

针对已有扩展的适配构建与标准发行镜像应明确区分；后续升级前需核对兼容性，避免覆盖已有功能。具体服务器、内部地址、部署和备份目录、账号、渠道标识、定制镜像标识及校验材料仅保留在本地私有运维记录。

## 验证结果

1. 候选使用原生解析构建标签，通过 service、types、database、repository、handler、router 六个相关包的完整测试及最终构建。
2. 首次源码包带入操作系统附加元数据文件，影响源码遍历与迁移文件名测试；清理隔离构建目录后全部通过，没有修改业务代码绕过检查。
3. 使用目标数据库的仅表结构副本，在隔离环境验证 903→906 升级；未复制业务正文或现有会话令牌。
4. 隔离环境通过正常注册登录，合成文档的目录冲突、结构化链接保存/重读、正文版本冲突、评论解决、全文搜索、未认证拒绝、系统版本、文档页面与 API 代理检查通过。
5. 部署后应用及相关服务运行正常，有健康检查的服务均正常；数据库迁移版本 906 且无 dirty 状态，结构化历史列、目录表与评论表存在。
6. 工作台路由、实际工作台脚本资源、登录页与 API 代理可访问，未认证文档接口返回 401。
7. 消息连接重新建立，检索依赖健康检查通过；没有向用户或群发送验收消息。
8. 切换前后既有数据数量核对一致，原有扩展源文件与兼容配置检查通过。

隔离验收结束后清理临时容器、测试卷、网络和临时凭据文件。详细日志与恢复定位材料留在内部运维记录，公开归档不包含业务明细。

## 备份与回滚边界

先在线预复制文件，再停止旧前端和应用，完成数据库、文件增量与任务状态的同一静默时间点备份，之后才迁移和启动新版。保留旧镜像和配置以支持恢复定位。

904–906 的降级迁移会删除结构化历史字段、目录和评论。升级后有写入时，不应直接回退旧镜像或执行 down；应先停止写入、核对期间变化，再按一致时间点恢复数据库、文件和任务状态。

本次确认备份生成、归档目录可读、隔离升级和上线验收；没有在生产环境演练完整数据库恢复。

## 已知边界

真实登录后的文档写入验收在隔离环境完成，部署环境只做非破坏性页面、资源、接口、结构与连通性检查。未重测真实模型问答质量、检索故障切换、大规模知识库性能或所有业务文档格式。
