# WeKnora 文档工作台目录切换提速

- 日期：2026-11-12。
- 关联：[[文档工作台-归档索引]]、[[WeKnora文档工作台-浏览正文排版]]、[[WeKnora文档工作台-自动保存与结构化正文]]。
- 状态：实现、验证、提交、推送、v1.8.11 发布及生产前端部署完成。

## 需求背景与定位

用户反馈点击左侧文档标题后，右侧正文约等待一秒，阅读切换不够流畅。代码检查发现：每次切换均清空正文、重新请求详情；未经在线编辑的文件要继续请求所有分片，正文可见时间受串行接口影响。结构化正文还会先生成 HTML 验证，再由计算属性生成一遍供页面显示。历史恢复同样存在重复详情请求。

本期没有读取真实业务文档或测量真实账号接口，不能将用户反馈的一秒全部归因于某个接口。使用相同合成数据与固定延迟进行可复现的前端对比。

## 设计决策与实现范围

- 文档阅读器实例内增加短时内存缓存和请求合并，不写本地存储。有效期 15 秒，最多 8 篇，序列化内容总量最多 200 万字符，超过容量的文档仍可阅读但不缓存；按最近访问淘汰。
- 目录标题鼠标进入或键盘聚焦 80ms 后预取详情和必要分片。连续移动只保留最后一个待启动目标，最多同时进行两项预取；正文点击优先，不被预取配额阻塞。工作台与知识库浏览模式均接入。
- 缓存命中时在同一更新周期内替换正文，不闪现骨架；预取进行中时点击复用同一请求。缓存键包含知识库、文档 ID、目录更新时间、类型与解析状态，不改变 API 或权限检查。
- 保存成功、恢复历史、重新学习、显式重试、账号/租户/知识库切换以及卸载时清理缓存。缓存清理后晚到请求不得回填；快速切换的旧请求不得覆盖当前正文；预取错误由正式打开时重试并展示，不隐藏权限错误。
- 结构化正文验证改为读取同一个计算属性，避免重复 HTML 生成；历史恢复仅请求一次详情。

## 验证结果

- 新增缓存与阅读器回归，覆盖预取/点击合并、同步回访、过期、失败重试、容量淘汰、预取并发限制、跨作用域晚到响应、保存/历史恢复失效、单次 HTML 渲染和文件分片/在线编辑正文优先级；最终定向 23 项通过。
- 类型检查和生产构建通过，构建仍有既有大包提示；差异空白检查通过。
- 最终前端全量 2,109 项：2,108 通过、1 项既有跳过、0 失败。
- 隔离 Chrome 分别运行纯净 v1.8.10 和本地优化版，使用相同合成文档与每次详情固定 400ms 延迟，测量目录点击至正文绘制（两帧后）耗时。对照结果：

| 场景 | v1.8.10 | 本地优化版 |
| --- | ---: | ---: |
| 首次打开且未预取 | 454ms | 451ms |
| 15 秒内切回已读文档 | 448ms | 32ms |
| 鼠标悬停预取完成后打开 | 441ms | 12ms |

- 预取场景为悬停 650ms 后点击，预取包含 80ms 防抖和 400ms 接口延迟。优化版回访与预取后点击均未增加详情请求；对照版本三种打开均重新请求。无浏览器运行时错误。这是单次受控合成对比，不代表生产延迟分布或所有文档的速度。

## 已知边界

首次未预取、缓存过期、超大文档或慢接口仍需等待网络；没有声明所有首次打开都达到几十毫秒。其他人修改的内容在目录未更新时最多可能复用 15 秒内的旧响应，缓存过期、显式重试或刷新后会获取最新内容；本机保存与恢复立即失效。缓存只复用数据，正文渲染仍需在选中后执行，超大正文或复杂图表的 CPU 开销不在本期完全解决。

没有新增后端接口、数据库迁移或依赖。本期已提交、推送并部署生产前端，不包含工作区内独立的摘要、标签、重排及运行环境改动。归档同步用户原本地 Obsidian 项目笔记，仓库保留副本与双链索引。
